- 규칙 문서: [`docs/분할규칙_v3_수정안.md`](docs/분할규칙_v3_수정안.md)

서버 없이 브라우저에서 모두 계산하고, IFC 파일은 어디에도 전송하지 않는다.

## 파일 구성과 담당

| 파일 | 내용 | 고칠 때 |
|---|---|---|
| `index.html` | 화면 뼈대 (카드, 버튼, 입력칸 배치) | 버튼·문구·입력칸을 추가하거나 옮길 때 |
| `style.css` | 색, 글꼴, 간격, 배치 | 디자인을 바꿀 때 |
| `js/core.js` | 규칙 1~6 판정, 최소 타설 단위, 구획 탐색, 비상 중단선(2장), 시공 중 재분할(3장) | 규칙·수식·알고리즘을 바꿀 때 |
| `js/ifc.js` | IFC(STEP) 읽기, 층·부재·그리드 추출, 회전 보정, 보 물량 | IFC에서 읽는 정보를 바꿀 때 |
| `js/ui.js` | 단계 전환, 입력 읽기, 결과·도면 그리기, 시공 기록 | 결과 표시나 화면 동작을 바꿀 때 |
| `js/sample.js` | 예제 IFC 모델 | 거의 안 고침 |
| `tests/` | 독립 검산 도구 | 규칙을 바꾸면 검산도 같이 |
| `docs/` | 규칙 문서 | 규칙을 바꾸면 문서도 같이 |

`index.html`은 `core.js → ifc.js → sample.js → ui.js` 순서로 불러온다. 순서를 바꾸면 동작하지 않는다.

## 내 컴퓨터에서 실행하기

`index.html`을 크롬으로 열면 된다. 설치할 것은 없다.

## 고친 뒤 꼭 검사하기

[Node.js](https://nodejs.org)를 설치한 뒤, 이 폴더에서:

```
node tests/run.js                              # 예제 + 무작위 비정형 평면 12개
node tests/run.js 30                           # 무작위 평면 30개 (더 꼼꼼히)
node tests/run.js 모델.ifc "지상 3층" 120        # 내 IFC의 한 층을 하루 120㎥로
```

검산 도구는 프로그램이 낸 결과를 **따로 다시 계산해서** 대조한다.

- 물량 보존: 칸·조각·단위·구역 물량의 합 = 총량
- 수식: 최대·최소 구역, 물량 불균형, 이음 길이 합, 구역 수 하한
- 규칙 1·2: 경계가 보를 지나는 모든 점이 순경간 가운데 1/3 안, 작은보 옆면에서 폭 × 2 밖
- 규칙 3·6: 슬래브 한가운데 꺾임 없음, 구역마다 한 덩어리
- 비상 중단선: 레미콘 대수, 중단선 수, 멈출 자리, 대표 선 선택
- 구획안을 못 찾으면, 제안한 하루 한도로 다시 계산해 실제로 나오는지

마지막 줄이 `실패 0건`이어야 올린다.

**자동 검산:** 코드를 올리거나 Pull Request를 만들면 GitHub이 같은 검산을 자동으로 돌린다. 저장소의 **Actions** 탭에서 결과를 본다(초록 체크 = 통과, 빨간 X = 실패). 컴퓨터에 아무것도 설치하지 않아도 된다.

## 함께 작업하는 방법

### 웹사이트에서 (설치 없이)

- **파일 하나 고치기:** 파일을 열고 오른쪽 위 연필 아이콘 → 고친 뒤 **Commit changes**
- **여러 파일을 같이 고치기:** 저장소 화면에서 키보드 **`.`(마침표)**를 누르면 브라우저 안에 편집기(github.dev)가 열린다. 여러 파일을 고친 뒤 왼쪽 소스 제어 아이콘에서 한 번에 Commit.
- **파일 올리기:** **Add file → Upload files**에 파일·폴더를 끌어다 놓기
- **큰 수정은 Pull Request로:** Commit할 때 *Create a new branch for this commit and start a pull request*를 고르면, 다른 팀원이 확인하고 **Merge**한다. 자동 검산이 초록 체크인지 보고 합친다.

### GitHub Desktop으로 (선택)

**처음 한 번**
1. [GitHub Desktop](https://desktop.github.com) 설치 → GitHub 계정으로 로그인
2. File → Clone repository → `dkde-commits/pour-zoning` 선택

**고칠 때마다**
1. 시작 전에 **Fetch origin → Pull** (다른 팀원의 수정을 먼저 받는다)
2. 파일을 고치고 `index.html`을 열어 확인, `node tests/run.js`로 검사
3. 왼쪽 아래에 무엇을 고쳤는지 한 줄 적고 **Commit to main** → **Push origin**

**충돌을 줄이는 약속**
- 같은 파일을 동시에 고칠 때는 채팅방에 먼저 알린다.
- 큰 수정은 브랜치를 만들어(Current branch → New branch) 작업하고, Pull Request로 다른 팀원이 확인한 뒤 합친다.
- 규칙을 바꾸면 `js/core.js`, `tests/check.js`, `docs/` 세 곳을 함께 고친다.

`main`에 올리면 1~2분 뒤 사이트에 자동 반영된다(GitHub Pages). 반영이 안 보이면 Ctrl+Shift+R.

## 적용 규칙 요약

| 규칙 | 내용 | 근거 |
|---|---|---|
| 1 | 보를 가로지를 때 순경간(지지 부재 면 사이) 가운데 1/3 안에서만 자른다 | KCS 3.6.1(1)·3.6.5(1), 수치는 ACI 318-14 26.5.6.2(b) |
| 2 | 작은보 옆면에서 폭의 2배 이내는 비우고, 그 큰보를 자르는 이음은 경사 인장철근으로 보강 | KCS 3.6.5(1) 단서, ACI 318 26.5.6.2(c) |
| 3 | 벽·코어·개구부를 지나지 않는다. 이음선은 슬래브 한가운데서 꺾지 않고 곧게 간다(T자 허용) | KCS 3.6.1(1)·3.6.5(1) |
| 4 | 캔틸레버는 자르지 않고 붙어 있는 구역에 넣는다 | KCS 3.6.4(1) |
| 5 | 그리드와 나란한 직선만 쓴다 | KCS 3.6.2(1)·3.7.1(3) |
| 6 | 한 구역은 하나로 이어져야 한다 | KCS 3.7.1(2) |

물량은 슬래브 + 슬래브 아래 보(보는 실제 놓인 칸에 배분). 구역 수 하한은 max(올림(총량 ÷ 하루 한도), 하루 한도의 절반을 넘는 단위 수). 자세한 내용과 판정 방법은 규칙 문서 참고.
